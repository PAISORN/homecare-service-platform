# Phase 4D — หลักฐานหน้างาน PIN และงานเพิ่มเติม

Phase 4D เพิ่มจุดยืนยันที่ตรวจสอบย้อนหลังได้ตั้งแต่ช่างถึงหน้างานจนส่งงานให้ลูกค้าตรวจรับ โดยยังไม่รวมการตรวจรับขั้นสุดท้าย การชำระเงิน การแชร์ตำแหน่ง หรือ Push Notification

## ขอบเขตที่ส่งมอบ

- ช่างแนบรูป `before`, `during`, `after` และ `additional_work` ลง private Storage bucket
- รูปทุกใบผูกกับงาน ผู้บันทึก ประเภทหลักฐาน และเวลา เป็น append-only
- ลูกค้าสร้าง PIN 6 หลัก อายุ 15 นาที; เก็บเฉพาะ hash และล็อกเมื่อกรอกผิด 5 ครั้ง
- รูปก่อนงานเป็นเงื่อนไขออก PIN เริ่มงาน และรูปหลังงานเป็นเงื่อนไขออก PIN จบงาน
- PIN เริ่มงานเปลี่ยน `technician_arrived -> in_progress`
- PIN จบงานเปลี่ยน `in_progress -> awaiting_acceptance`
- ช่างส่งคำขอเพิ่มงานพร้อมขอบเขต เหตุผล รูปหลักฐาน ค่าแรง และค่าวัสดุ
- ระหว่างรอคำตอบ งานอยู่ `awaiting_additional_work_approval` และทำคำขอซ้อนไม่ได้
- ราคาเดิมไม่เปลี่ยนจนลูกค้าอนุมัติ; เมื่ออนุมัติ ยอดค่าแรง/วัสดุและค่าคอมมิชชันที่คำนวณจากค่าแรงจะอัปเดตใน transaction เดียว
- การออก/ใช้ PIN การลงหลักฐาน และการตัดสินใจเรื่องงานเพิ่มมี Audit Log; การเปลี่ยนสถานะเพิ่มใน Job Status Events

## ขอบเขตสิทธิ์

- เฉพาะช่างที่ได้รับมอบหมายและผ่านการตรวจสอบอัปโหลดหลักฐานและกรอก PIN
- เฉพาะลูกค้าเจ้าของงานออก PIN และอนุมัติหรือปฏิเสธงานเพิ่มเติม
- คู่สัญญาเห็นหลักฐานและคำขอของงานตัวเองผ่าน RLS; ตาราง PIN ไม่เปิดให้อ่านตรง
- Storage ใช้ registry-first reservation และ policy แบบ bucket-scoped; reservation ที่อัปโหลดไม่สำเร็จลบได้เฉพาะเมื่อไม่มี object จริง

## งานที่เลื่อนไป Phase ถัดไป

- ลูกค้าตรวจรับ/เปิดข้อโต้แย้งและกรอบเวลา 48 ชั่วโมง
- Payment intent, capture, payout และ refund
- Push Notification, Deep Link และตำแหน่ง/ETA
