# Phase 4C — แชตในงานบริการ

Phase นี้เปิดช่องทางสนทนาแบบถาวรระหว่างลูกค้ากับช่างหลังเกิดงานบริการ โดยข้อความในฐานข้อมูลเป็นหลักฐานต้นทาง และ Realtime เป็นเพียงช่องทางแจ้งข้อความใหม่ให้หน้าจออัปเดตทันที

## ขอบเขตที่ส่งมอบ

- งานบริการทุกงานมี `chat_rooms` หนึ่งห้อง และมีสมาชิกสองคนจากคู่สัญญาของงานใน `chat_room_memberships`
- งานเดิมได้รับการ backfill ห้องและสมาชิก ส่วนงานใหม่สร้างห้องและสมาชิกอัตโนมัติในธุรกรรมเดียวกับการสร้างงาน
- ข้อความเก็บถาวรใน `chat_messages` และแก้ไขหรือลบผ่าน client ไม่ได้
- RPC ส่งข้อความใช้ผู้ส่งจาก `auth.uid()` ตรวจ active account และ membership ฝั่งฐานข้อมูล
- `client_message_id` ป้องกันข้อความซ้ำจากการ retry โดยไม่ยอมให้ใช้รหัสเดิมกับเนื้อหาหรือห้องอื่น
- สมาชิกอ่านห้อง membership ของตน และข้อความได้ผ่าน RLS; บัญชีอื่นและ anonymous อ่านหรือส่งไม่ได้
- การ insert ข้อความเรียก database trigger เพื่อส่ง `message_created` ไปยัง private Realtime Broadcast topic ของห้อง
- `realtime.messages` มี policy ให้รับ Broadcast ได้เฉพาะสมาชิกของ topic นั้น และ client เปิด channel ด้วย `private: true`
- หน้ารายละเอียดงานของลูกค้าและช่างมีทางเข้าแชต แสดงข้อความตามเวลา และส่งข้อความได้สูงสุด 2,000 ตัวอักษร
- หน้าจอรองรับ loading, retry, disabled/sending, keyboard safe area, empty state และถอด Realtime channel เมื่อออกจากหน้าจอ

## ขอบเขตที่ยังไม่รวม

- รูป วิดีโอ ตำแหน่ง ไฟล์แนบ และข้อความสถานะจากระบบ
- สถานะอ่านแล้ว การพิมพ์อยู่ Presence การค้นหา และ pagination ย้อนหลังเกิน 100 ข้อความล่าสุด
- push notification, deep link จาก notification, การโทรแบบปกปิดเบอร์ และคำขอให้โทรกลับ
- เครื่องมือผู้ดูแลสำหรับ moderation, export, ข้อร้องเรียน และข้อพิพาท
- หลักฐานก่อน–ระหว่าง–หลังงาน, PIN, คำขอเพิ่มงาน และการตรวจรับ

ข้อความ durable จะไม่ถูกคัดลอกลง Audit Log เพื่อลดการทำสำเนาข้อมูลส่วนบุคคลโดยไม่จำเป็น ประวัติใน `chat_messages` เป็นแหล่งข้อมูลหลักของการสนทนา
