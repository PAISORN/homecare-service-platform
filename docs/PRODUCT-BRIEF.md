# HomeCare — Product Brief

## 1. ภาพรวมโครงการ

**ชื่อระบบ:** HomeCare  
**ประเภทระบบ:** แพลตฟอร์มตลาดกลางบริการช่างสำหรับบ้าน ห้องเช่า คอนโด ร้านค้า สำนักงาน และสถานที่ทั่วไป  
**แนวคิดหลัก:** เชื่อมต่อผู้ที่ต้องการใช้บริการซ่อมกับช่างหลากหลายสาขาที่ผ่านการตรวจสอบ โดยดูแลกระบวนการตั้งแต่แจ้งปัญหา จับคู่ช่าง เสนอราคา นัดหมาย ซ่อม ตรวจรับ ชำระเงิน ไปจนถึงการรับประกันงาน

**Positioning:** HomeCare เป็น **ตลาดบริการแบบควบคุม** ไม่ใช่พื้นที่ลงประกาศหรือแสดงเบอร์โทรโดยตรง ลูกค้าและช่างค้นพบกันผ่านการจัดหาโดยระบบหรือ feed ที่ผ่านการคัดกรอง แต่ทุกการจ้างต้องเข้าสู่กระบวนการที่แพลตฟอร์มควบคุมคุณภาพ ความปลอดภัย การยืนยันขอบเขตและราคา การนัดหมาย การชำระเงิน การตรวจรับ และความรับผิดชอบหลังจบงาน

**สโลแกนเบื้องต้น:** “เรียกช่างง่าย ซ่อมไว มั่นใจทุกงาน”

**คำอธิบายแบรนด์:** “บริการช่างดูแลบ้าน” ต้องแสดงร่วมกับชื่อหรือโลโก้ในจุดที่ผู้ใช้ยังไม่รู้จักแบรนด์ เพื่อลดความสับสนกับบริการดูแลผู้ป่วยหรือผู้สูงอายุ

**ชื่อสำหรับหน้าร้านแอปและการค้นหา:** “HomeCare: บริการช่างดูแลบ้าน”

โลโก้ใช้ภาพแทนบ้านร่วมกับเครื่องมือช่างและไม่ใช้สัญลักษณ์ทางการแพทย์ ชื่อหลักยังคงเป็น HomeCare โดยไม่เพิ่ม Fix หรือ Service เข้าไปในชื่อแบรนด์

## 2. เป้าหมายของระบบ

- ทำให้ผู้ใช้สามารถหาช่างที่เหมาะสมและน่าเชื่อถือได้ง่าย
- ลดปัญหาราคาไม่ชัดเจน ช่างไม่ตรงนัด และไม่มีผู้รับผิดชอบหลังซ่อม
- สร้างช่องทางรับงานและรายได้ให้ช่างที่มีทักษะ
- เก็บประวัติงานซ่อมของแต่ละสถานที่อย่างเป็นระบบ
- สร้างมาตรฐานด้านราคา คุณภาพ ความปลอดภัย และการรับประกันงาน
- รองรับการขยายบริการไปยังบ้าน คอนโด หอพัก ร้านค้า สำนักงาน และผู้ดูแลอาคาร

## 3. กลุ่มผู้ใช้งานและบทบาท

### 3.1 ลูกค้าผู้ใช้บริการ

กลุ่มเป้าหมาย ได้แก่ เจ้าของบ้าน ผู้เช่า เจ้าของคอนโด ผู้ดูแลหอพัก ร้านค้า สำนักงาน และผู้ดูแลอาคาร

MVP ให้ลูกค้าสมัครด้วยเบอร์โทรและ OTP เป็นช่องทางหลัก ขอชื่อที่ใช้ติดต่อเมื่อเริ่มจองครั้งแรก และให้อีเมลเป็นตัวเลือกสำหรับใบเสร็จหรือการกู้คืนบัญชี ไม่บังคับส่งบัตรประชาชนสำหรับการสมัครทั่วไป แต่ต้องยืนยันช่องทางชำระเงินก่อนยืนยันงานที่มีค่าใช้จ่าย ระบบอาจขอข้อมูลเพิ่มเฉพาะกรณีงานมูลค่าสูง พฤติกรรมเสี่ยง การคืนเงิน หรือข้อพิพาท

ความสามารถหลัก:

- สมัครสมาชิกด้วยเบอร์โทรศัพท์และ OTP และเพิ่มอีเมลได้ภายหลัง
- จัดการข้อมูลส่วนตัวและช่องทางติดต่อ
- เพิ่มและจัดการสถานที่รับบริการได้หลายแห่ง
- เลือกประเภทงานซ่อมและระบุรายละเอียดอาการ
- แนบรูปภาพหรือวิดีโอของปัญหา
- ระบุระดับความเร่งด่วน
- เลือกวันและเวลานัดหมาย
- เลือกช่างเองหรือให้ระบบจับคู่ช่าง
- รับและเปรียบเทียบใบเสนอราคา
- ยืนยันราคาและขอบเขตงานก่อนเริ่มงาน
- แชตหรือโทรหาช่างผ่านระบบ
- ติดตามสถานะงานและตำแหน่งช่าง
- ตรวจรับงานและชำระเงิน
- รับใบเสร็จหรือหลักฐานการชำระเงิน
- ให้คะแนนและรีวิวช่าง
- แจ้งปัญหาหรือขอใช้สิทธิ์รับประกัน
- ดูประวัติการซ่อมแยกตามสถานที่

### 3.2 ช่างผู้ให้บริการ

MVP รองรับ **ช่างรายบุคคล** เท่านั้น หนึ่งบัญชีผูกกับบุคคลที่ผ่านการยืนยันตัวตนและบัญชีรับเงิน ช่างที่แสดงต่อลูกค้าต้องเป็นผู้ไปหน้างานและรับผิดชอบงานนั้น ห้ามส่งต่องานให้บุคคลอื่น และยังไม่รองรับบัญชีทีม บริษัท หัวหน้าทีม การแจกงานให้ลูกทีม หรือการแบ่งรายได้ งานที่จำเป็นต้องมีผู้ช่วยอยู่นอกขอบเขตบริการช่วงแรกจนกว่าจะมีระบบตรวจสอบสมาชิกทีม

ความสามารถหลัก:

- สมัครและยืนยันตัวตน
- ส่งบัตรประชาชน ภาพใบหน้า บัญชีธนาคาร และเอกสารรับรองที่เกี่ยวข้อง
- เลือกประเภทงาน ความเชี่ยวชาญ และพื้นที่ให้บริการ
- ระบุประสบการณ์ ใบรับรอง และผลงานที่ผ่านมา
- กำหนดวันและเวลาที่พร้อมรับงาน
- รับ ปฏิเสธ หรือเสนอราคางาน
- ดูรายละเอียดและตำแหน่งหน้างาน
- แชตหรือโทรหาลูกค้าผ่านระบบ
- เปลี่ยนสถานะการเดินทางและสถานะงาน
- ใช้ PIN เพื่อยืนยันการเริ่มและสิ้นสุดงาน
- บันทึกรูปก่อนซ่อม ระหว่างซ่อม และหลังซ่อม
- เพิ่มรายการค่าแรง วัสดุ และอะไหล่
- ขออนุมัติงานเพิ่มเติมหรือค่าใช้จ่ายเพิ่มเติมจากลูกค้า
- ดูรายได้ ค่าธรรมเนียม ยอดคงเหลือ และประวัติการถอนเงิน
- ดูคะแนน รีวิว และสถิติการทำงาน

### 3.3 ผู้ดูแลหอพัก คอนโด หรืออาคาร

บทบาทนี้อยู่นอกขอบเขต MVP และวางไว้สำหรับระยะหลัง เมื่อต้องรองรับหลายอาคาร หลายห้อง สิทธิ์ผู้แจ้งงาน ผู้อนุมัติค่าใช้จ่าย รายงาน และการวางบิลแบบองค์กร ใน MVP เจ้าของหรือผู้ดูแลรายย่อยใช้บทบาทลูกค้าและเพิ่มสถานที่รับบริการได้หลายแห่ง

- เพิ่มและจัดการหลายอาคาร ห้อง หรือพื้นที่
- แจ้งงานแทนผู้พักอาศัย
- กำหนดผู้มีสิทธิ์แจ้งงานหรืออนุมัติค่าใช้จ่าย
- ติดตามงานซ่อมทั้งหมดของแต่ละพื้นที่
- ดูประวัติ ค่าใช้จ่าย และสถิติการซ่อม
- ดาวน์โหลดรายงานและเอกสารประกอบ

### 3.4 ผู้ดูแลระบบ

- ตรวจสอบและอนุมัติช่าง
- จัดการลูกค้า ช่าง ผู้ดูแลอาคาร และสิทธิ์ใช้งาน
- จัดการหมวดงาน รายการบริการ และราคาอ้างอิง
- ตรวจสอบงาน ใบเสนอราคา การชำระเงิน และการถอนเงิน
- กำหนดค่าคอมมิชชันและค่าธรรมเนียม
- ตรวจสอบคะแนน คุณภาพงาน และพฤติกรรมการให้บริการ
- จัดการข้อร้องเรียน การคืนเงิน และข้อพิพาท
- ระงับบัญชีหรือจำกัดสิทธิ์ผู้ใช้ที่มีปัญหา
- ดู Dashboard จำนวนงาน รายได้ อัตราสำเร็จ และคุณภาพบริการ

## 4. หมวดบริการ

หมวดงานที่สามารถรองรับในอนาคต:

- ระบบไฟฟ้า
- ประปาและสุขภัณฑ์
- เครื่องปรับอากาศ
- เครื่องใช้ไฟฟ้า
- ปั๊มน้ำและถังเก็บน้ำ
- งานช่างทั่วไป
- งานไม้และเฟอร์นิเจอร์
- ประตู หน้าต่าง และกุญแจ
- หลังคาและงานรั่วซึม
- ทาสีและซ่อมผนัง
- กล้องวงจรปิด อินเทอร์เน็ต และระบบสื่อสาร
- ทำความสะอาด
- ดูแลสวน
- ตรวจสอบบ้านหรืออาคาร

MVP เริ่มด้วย 3 หมวดเท่านั้น:

1. **เครื่องปรับอากาศ:** ล้างแอร์ใช้ราคามาตรฐานตามชนิดและขนาดเครื่อง ส่วนงานซ่อมใช้การประเมินจากหลักฐานหรือตรวจหน้างานก่อนเสนอราคา
2. **ประปา:** งานเปลี่ยนอุปกรณ์ที่ขอบเขตชัดใช้ราคามาตรฐาน ส่วนงานน้ำรั่ว ท่อแตก หรือหาสาเหตุไม่ได้ใช้การตรวจหน้างานก่อนเสนอราคา
3. **ไฟฟ้า:** งานติดตั้งปลั๊ก สวิตช์ หรือโคมไฟที่ขอบเขตชัดใช้ราคามาตรฐาน ส่วนงานไฟผิดปกติหรือมีความเสี่ยงใช้การตรวจหน้างานก่อนเสนอราคา

รายการบริการ ราคาอ้างอิง คำถามคัดกรอง ขอบเขต และเงื่อนไขรับประกันรุ่น Pilot กำหนดไว้ใน [`SERVICE-CATALOG-MVP.md`](SERVICE-CATALOG-MVP.md) โดยราคาเหล่านี้ยังต้องผ่านการทดลองหน้างานก่อนเปิดขายจริง

ยังไม่รวม “ซ่อมเครื่องใช้ไฟฟ้าทุกชนิด” และ “ช่างทั่วไป” ใน MVP เพราะเป็นหมวดที่ขอบเขต ทักษะ อะไหล่ ราคา และเงื่อนไขรับประกันแตกต่างกันมาก

แต่ละหมวดควรมีแบบสอบถามอาการเฉพาะงาน เพื่อช่วยประเมินความเร่งด่วน ความเสี่ยง และประเภทช่าง เช่น งานไฟฟ้าควรถามว่าไฟดับทั้งบ้านหรือบางจุด มีกลิ่นไหม้ ควัน หรือประกายไฟหรือไม่

MVP ไม่ให้บริการฉุกเฉินและไม่รับประกันเวลาถึงหน้างาน ลูกค้าเลือก “เร็วที่สุดที่ว่าง” หรือนัดหมายล่วงหน้าตามเวลาว่างจริง หากแบบสอบถามพบเหตุที่อาจเป็นอันตรายต่อชีวิตหรือทรัพย์สิน เช่น ไฟไหม้ กลิ่นแก๊ส หรือน้ำใกล้อุปกรณ์ไฟฟ้า ระบบต้องหยุดขั้นตอนจองปกติ แสดงคำแนะนำความปลอดภัยและช่องทางฉุกเฉินที่เหมาะสม และไม่สื่อว่า HomeCare ทดแทนหน่วยฉุกเฉิน

## 5. ขั้นตอนการให้บริการ

1. ลูกค้าเลือกสถานที่และแจ้งปัญหา
2. ลูกค้าเลือกหมวดงาน ตอบคำถามอาการ และแนบรูปหรือวิดีโอ
3. ระบบประเมินประเภทงาน ความเร่งด่วน และจับคู่ช่างตามทักษะ พื้นที่ และเวลาว่าง
4. ช่างตรวจสอบรายละเอียดและเสนอราคา หรือเสนอค่านัดสำรวจ
5. ลูกค้าตรวจสอบขอบเขตงาน ราคา และยืนยันการจ้าง
6. ลูกค้าและช่างยืนยันวันเวลานัดหมาย
7. ช่างเดินทางถึงหน้างานและใช้ PIN ยืนยันการเริ่มงาน
8. ช่างบันทึกรูปก่อนซ่อมและดำเนินงาน
9. หากมีงานหรือค่าใช้จ่ายเพิ่มเติม ช่างต้องส่งคำขอให้ลูกค้าอนุมัติก่อน
10. ช่างบันทึกรูปหลังซ่อมและส่งงานให้ตรวจรับ
11. ลูกค้าตรวจรับและยืนยันการชำระเงิน
12. ระบบจ่ายเงินให้ช่างหลังหักค่าธรรมเนียม
13. ลูกค้าให้คะแนนและรีวิว
14. งานเข้าสู่ช่วงรับประกันตามเงื่อนไข

## 6. สถานะงาน

- แบบร่าง
- รอจับคู่ช่าง
- รอช่างรับงาน
- รอเสนอราคา
- รอลูกค้ายืนยันราคา
- นัดหมายแล้ว
- ช่างกำลังเดินทาง
- ช่างถึงหน้างานแล้ว
- กำลังดำเนินงาน
- รออนุมัติงานเพิ่มเติม
- รอตรวจรับ
- เสร็จสิ้น
- อยู่ในช่วงรับประกัน
- ยกเลิก
- มีข้อร้องเรียนหรือข้อพิพาท

ระบบควรเก็บวันที่ เวลา ผู้ดำเนินการ และหมายเหตุของทุกการเปลี่ยนสถานะเพื่อใช้ตรวจสอบย้อนหลัง

### 6.1 การยกเลิกและไม่มาตามนัด

- ก่อนช่างตอบรับหรือก่อนลูกค้าเลือกช่าง ลูกค้ายกเลิกได้โดยไม่มีค่าธรรมเนียม
- หลังยืนยันนัด ลูกค้ายกเลิกได้โดยไม่มีค่าธรรมเนียมหากเหลือมากกว่า 24 ชั่วโมง
- หากเหลือน้อยกว่า 24 ชั่วโมงหรือช่างเริ่มเดินทางแล้ว ระบบอาจเรียกเก็บค่าธรรมเนียมตามกฎที่ผู้ดูแลตั้งค่าและแสดงให้ลูกค้าเห็นก่อนยืนยันนัด
- หากลูกค้าไม่อยู่หน้างาน ช่างต้องบันทึกเวลา ตำแหน่ง และหลักฐานก่อนขอค่าเสียเวลา
- หากช่างยกเลิก ลูกค้าได้รับเงินคืนเต็มจำนวนและระบบให้สิทธิ์จัดหาช่างใหม่ก่อน
- หากช่างไม่มาตามนัด ลูกค้าได้รับเงินคืนเต็มจำนวน ระบบบันทึกเหตุเพื่อใช้ควบคุมคุณภาพช่าง และผู้ดูแลอาจให้เครดิตชดเชย
- ผู้ดูแลยกเว้นค่าธรรมเนียมได้เมื่อมีเหตุและหลักฐานสมควร

จำนวนเงิน ช่วงเวลา และเงื่อนไขยกเว้นต้องตั้งค่าได้จากระบบ ไม่ฝังค่าตายตัวในแอป และต้องแสดงต่อผู้เกี่ยวข้องก่อนเกิดภาระผูกพัน

## 7. รูปแบบการกำหนดราคา

HomeCare ใช้ **รูปแบบราคาผสม** โดยรายการบริการแต่ละรายการต้องระบุรูปแบบราคาให้ชัดเจนก่อนลูกค้าส่งคำขอ รองรับ 3 รูปแบบหลัก:

1. **ราคามาตรฐาน:** ราคาตายตัวสำหรับขอบเขตที่กำหนดได้ชัด เช่น ล้างแอร์ เปลี่ยนก๊อก หรือติดตั้งพัดลม โดยตัวเลือกที่ทำให้ราคาเพิ่มต้องแสดงก่อนยืนยัน
2. **ประเมินจากหลักฐาน:** ช่างประเมินจากรายละเอียด รูป หรือวิดีโอ แล้วส่งใบเสนอราคาให้ลูกค้ายืนยันก่อนนัดหมายหรือเริ่มงาน
3. **ตรวจหน้างานก่อนเสนอราคา:** ลูกค้ายืนยันค่าตรวจหน้างานก่อน เหมาะกับงานที่ยังระบุสาเหตุหรือขอบเขตไม่ได้ จากนั้นช่างจึงส่งใบเสนอราคาซ่อมแยกให้ลูกค้าตัดสินใจ

โครงสร้างราคา:

- ค่าเข้าตรวจสอบ
- ค่าแรง
- ค่าวัสดุและอะไหล่
- ค่าเดินทาง
- ค่าบริการเร่งด่วน
- ส่วนลดหรือคูปอง
- ค่าธรรมเนียมแพลตฟอร์ม
- ภาษี (ถ้ามี)
- ยอดชำระรวม

หลักการสำคัญ: ห้ามใช้คำว่า “ราคาเริ่มต้น” โดยไม่อธิบายเงื่อนไขที่อาจทำให้ราคาเปลี่ยน หลังเริ่มงาน ช่างไม่สามารถแก้ไขราคาหรือเพิ่มขอบเขตงานโดยพลการ การเปลี่ยนแปลงทุกครั้งต้องมีรายละเอียด เหตุผล รูปหลักฐาน ราคาเพิ่ม และการยืนยันจากลูกค้าในระบบก่อนดำเนินการ

## 8. ความน่าเชื่อถือและความปลอดภัย

**การรับประกันงาน:** สิทธิ์ให้ลูกค้าขอแก้ไขอาการเดิมที่เกิดจากคุณภาพการซ่อมหรือติดตั้งภายในระยะที่กำหนดสำหรับรายการบริการ เช่น 7, 15 หรือ 30 วัน ไม่รวมปัญหาใหม่ การใช้งานผิดวิธี หรือส่วนที่อยู่นอกขอบเขตงาน

- การรับประกันอะไหล่แยกจากการรับประกันงานและเป็นไปตามเงื่อนไขที่ระบุในใบเสนอราคา
- ระยะรับประกัน ขอบเขต และข้อยกเว้นต้องแสดงก่อนลูกค้าชำระเงิน
- ลูกค้าเปิดคำขอรับประกันจากงานเดิมพร้อมคำอธิบาย รูป หรือวิดีโอ
- ช่างเดิมได้รับโอกาสนัดกลับไปแก้โดยไม่คิดค่าแรงสำหรับกรณีที่อยู่ในเงื่อนไข
- หากช่างปฏิเสธ แก้ไม่สำเร็จ หรือไม่พร้อมให้บริการ ผู้ดูแลสามารถจัดช่างอื่น คืนเงินบางส่วน หรือคืนเงินเต็มจำนวนตามหลักฐานและนโยบาย

- ยืนยันบัตรประชาชนและใบหน้าของช่าง
- ยืนยันเบอร์โทรและอีเมล
- ตรวจสอบบัญชีธนาคารให้ชื่อตรงกับผู้สมัคร
- เก็บหมวดงาน ทักษะ ประสบการณ์ พื้นที่บริการ และตัวอย่างผลงานหรือหลักฐานประสบการณ์
- ตรวจใบรับรองสำหรับรายการบริการที่ระบบกำหนดว่าจำเป็น
- ให้ช่างยอมรับข้อตกลงการให้บริการ นโยบายยกเลิก การรับประกัน และข้อห้ามส่งต่องาน
- ผู้ดูแลตรวจและอนุมัติช่างด้วยคนใน MVP ก่อนที่ช่างจะโพสต์ผลงาน แสดงความสนใจงาน หรือรับเงินได้
- แสดงสถานะการตรวจสอบแยกตามความหมาย เช่น “ยืนยันตัวตนแล้ว” “ตรวจบัญชีรับเงินแล้ว” และ “ตรวจใบรับรองแล้ว” ห้ามใช้ป้ายรวมที่ทำให้เข้าใจว่าแพลตฟอร์มรับรองทุกทักษะของช่าง
- แสดงจำนวนงานสำเร็จ อัตรายกเลิก และคะแนนเฉลี่ย
- คะแนนแยกด้านคุณภาพ ตรงเวลา ราคา และมารยาท
- รีวิวได้เฉพาะงานที่เสร็จสิ้นและชำระผ่าน HomeCare โดยแสดงป้าย “งานยืนยันแล้ว”
- ลูกค้าให้คะแนนรวม 1–5 ดาว คะแนนย่อยด้านคุณภาพงาน การตรงเวลา ความชัดเจนของราคา และมารยาท พร้อมแท็กสำเร็จรูปและข้อความเพิ่มเติมแบบไม่บังคับ
- ลูกค้าแก้ไขรีวิวได้ภายใน 7 วันหรือระหว่างกระบวนการข้อร้องเรียน ช่างตอบรีวิวได้หนึ่งครั้งแต่แก้คะแนนหรือลบรีวิวเองไม่ได้
- รีวิวที่มีข้อมูลส่วนบุคคล คำหยาบ หรือข้อกล่าวหาร้ายแรงต้องเข้าสู่การตรวจสอบ และรีวิวของงานที่มีข้อพิพาทจะยังไม่เผยแพร่จนกว่าจะได้ข้อยุติ
- คะแนนโปรไฟล์คำนวณจากงานที่ยืนยันแล้วเท่านั้นและต้องแสดงจำนวนรีวิวควบคู่กัน
- ผลงานในโปรไฟล์ควรเชื่อมโยงจากงานจริงในระบบ
- ใช้ PIN หรือ QR ยืนยันก่อนเริ่มและจบงาน
- ช่างแชร์ตำแหน่งเฉพาะเมื่อกด “กำลังเดินทาง” สำหรับงานที่จับคู่แล้ว ลูกค้าเห็นตำแหน่งและ ETA โดยประมาณ และระบบหยุดแชร์เมื่อถึงหน้างาน งานถูกยกเลิก หรือหมดเวลาที่กำหนด
- แอปขอสิทธิ์ตำแหน่งเฉพาะตอนใช้งาน ก่อนตอบรับงานระบบใช้เขตบริการและระยะทางโดยประมาณ ลูกค้าไม่เห็นที่อยู่หรือตำแหน่งของช่างนอกเวลางาน
- หากแผนที่สดยังไม่พร้อม MVP ใช้สถานะการเดินทางและ ETA ที่ช่างระบุแทนได้
- มีปุ่มขอความช่วยเหลือและช่องทางติดต่อศูนย์บริการ
- ใช้แชตในแอปเป็นช่องทางหลักและเปิดเมื่อจับคู่หรือเลือกช่างแล้ว ไม่เปิดแชตจากโพสต์ผลงานโดยตรง
- แชตรองรับข้อความ รูป วิดีโอ ตำแหน่งนัดหมาย และข้อความสถานะจากระบบ พร้อมเก็บประวัติเป็นหลักฐานของราคา งานเพิ่มเติม และข้อพิพาท
- ตรวจจับข้อมูลติดต่อหรือลิงก์ภายนอกและเตือนว่าการทำธุรกรรมนอกระบบไม่ได้รับความคุ้มครองจาก HomeCare
- ใช้หมายเลขโทรศัพท์แบบปกปิดตัวจริงเมื่อผู้ให้บริการพร้อมรองรับ หากยังไม่พร้อม MVP ให้ใช้แชตและคำขอให้โทรกลับโดยไม่แสดงเบอร์บน feed
- ปิดการเริ่มบทสนทนาใหม่เมื่อพ้นช่วงรับประกัน แต่ผู้เกี่ยวข้องยังอ่านประวัติเดิมได้ตามนโยบายเก็บข้อมูล
- มีระบบพักเงินจนกว่าลูกค้าจะตรวจรับ
- กำหนดระยะรับประกัน เช่น 7, 15 หรือ 30 วันตามประเภทงาน
- มีกระบวนการร้องเรียน ไกล่เกลี่ย คืนเงิน และชดเชย
- บันทึก Audit Log สำหรับการเปลี่ยนแปลงสำคัญ

## 9. ระบบจับคู่ช่าง

MVP ใช้รูปแบบ **ตลาดบริการแบบควบคุม** ไม่ใช่ตลาดรายชื่อสาธารณะหรือการประมูลราคา โดยมี 3 ช่องทางเริ่มต้นงาน:

1. ลูกค้าเลือกบริการมาตรฐานและดูราคาก่อนจอง
2. ลูกค้าแจ้งอาการเพื่อให้ระบบจัดหาช่างที่เหมาะสม
3. ลูกค้าเลือกช่างจากโพสต์ผลงานของช่างที่ผ่านการตรวจสอบ

ไม่ว่าลูกค้าจะเริ่มจากช่องทางใด ทุกการจ้างต้องสร้างเป็นงานในระบบและผ่านการยืนยันขอบเขต ราคา นัดหมาย การชำระเงิน การตรวจรับ และการรับประกันของ HomeCare

ปัจจัยที่ใช้ในการจับคู่:

- ประเภทงานและทักษะของช่าง
- ระยะทางจากสถานที่ให้บริการ
- พื้นที่ที่ช่างกำหนดว่าสามารถรับงานได้
- วันและเวลาว่าง
- คะแนนและจำนวนงานสำเร็จ
- อัตราการตอบรับและอัตราการยกเลิก
- ระดับราคาหรือราคาอ้างอิง
- ความเร่งด่วนของงาน
- ใบรับรองที่จำเป็น

ระยะแรกใช้กฎแบบ Rule-based โดยจัดลำดับจาก “ทักษะตรง + อยู่ในพื้นที่ + พร้อมตามเวลา + คุณภาพผ่านเกณฑ์” ลูกค้าเห็นโปรไฟล์ คะแนน จำนวนงานสำเร็จ และข้อมูลการยืนยันตัวตนก่อนยืนยันใช้บริการ และสามารถขอจับคู่ใหม่ได้ตามเงื่อนไข

ฝั่งช่างมี feed **งานที่เหมาะกับคุณ** ซึ่งแสดงเฉพาะงานที่ตรงกับหมวด ทักษะ เขตบริการ และเวลาว่างของช่าง ก่อนจับคู่สำเร็จต้องปิดบังชื่อเต็ม เบอร์โทร และที่อยู่ละเอียดของลูกค้า ช่างสามารถแสดงความสนใจหรือเสนอราคาตามรูปแบบราคาของงาน แต่ไม่เห็นข้อเสนอของช่างรายอื่นและไม่มีการประมูลแข่งลดราคา

**รายชื่อช่างที่สนใจ:** ระบบคัดกรองและจัดอันดับช่างที่เหมาะสมก่อนเปิดให้ตอบรับ แล้วรวบรวมตัวเลือกให้ลูกค้าเปรียบเทียบไม่เกิน 3 คน ไม่ใช้ลำดับผู้กดตอบรับเพียงอย่างเดียว งานราคามาตรฐานใช้ราคากลางเดียวกัน ส่วนงานประเมินจากหลักฐานให้ช่างส่งขอบเขตและราคาแบบปิดโดยไม่เห็นข้อเสนอของผู้อื่น ลูกค้าเลือกช่างหนึ่งคน แล้วระบบปิดคำขอของช่างรายอื่น หากไม่มีผู้สนใจ ระบบขยายขอบเขตการค้นหาตามกฎหรือส่งให้ผู้ดูแลช่วยจัดหา

ฝั่งลูกค้ามี feed **ผลงานจากช่าง** ซึ่งแสดงโพสต์จากช่างที่ผ่านการตรวจสอบ ลูกค้าดูโปรไฟล์และขอใช้บริการช่างเจ้าของโพสต์ได้ แต่ห้ามโพสต์ข้อมูลติดต่อเพื่อชักชวนให้ทำธุรกรรมนอกระบบ

**โพสต์ผลงาน:** เนื้อหาแบบมีโครงสร้างที่ช่างใช้แสดงผลงานและเชื่อมลูกค้าเข้าสู่การขอใช้บริการ ไม่ใช่โพสต์โซเชียลอิสระ หนึ่งโพสต์ประกอบด้วยรูปหรือวิดีโอ ชื่อผลงาน คำอธิบายสั้น หมวดงาน ประเภทบริการ พื้นที่ให้บริการระดับเขตหรืออำเภอ ราคาอ้างอิงหรือสถานะขอประเมินราคา และปุ่มขอใช้บริการช่างคนนี้

- แสดงป้าย “ผลงานจากงานในระบบ” เฉพาะโพสต์ที่เชื่อมโยงและตรวจสอบจากงานที่เสร็จสิ้นจริง
- รูปก่อน–หลังเป็นหลักฐานของงานและไม่เป็นสื่อสาธารณะโดยอัตโนมัติ หากช่างต้องการใช้ต้องส่งคำขอพร้อมตัวอย่างรูปและข้อความให้ลูกค้าอนุญาตแยกจากการตรวจรับงาน
- ก่อนเผยแพร่ต้องปิดบังใบหน้า เลขห้อง บ้านเลขที่ เอกสาร ป้ายทะเบียน และข้อมูลส่วนตัว ลูกค้าถอนความยินยอมได้ภายหลังและระบบต้องซ่อนโพสต์ที่เกี่ยวข้อง
- หากไม่ได้รับอนุญาต ช่างไม่สามารถสร้างโพสต์ใหม่จากรูปของงานนั้น ผู้ดูแลสามารถปฏิเสธหรือนำโพสต์ลงเมื่อพบความเสี่ยงด้านความเป็นส่วนตัว
- ทุกโพสต์ต้องผ่านการตรวจเนื้อหาอัตโนมัติหรือการอนุมัติก่อนเผยแพร่
- ห้ามใส่เบอร์โทร ไอดีแชต ลิงก์ หรือข้อความชักชวนให้ติดต่อนอกระบบ
- MVP รองรับการบันทึกและแชร์โพสต์ แต่ยังไม่มีความคิดเห็น การติดตามบัญชี หรือระบบยอดผู้ติดตาม

## 10. การชำระเงินและรายได้

ช่องทางชำระเงินที่ควรรองรับ:

- PromptPay QR
- บัตรเครดิตหรือเดบิต
- Mobile Banking ผ่าน Payment Gateway

MVP ไม่รองรับเงินสด ลูกค้าต้องชำระผ่านช่องทางในระบบหลังยืนยันขอบเขตและราคา เพื่อให้ HomeCare ตรวจสอบการรับเงิน คืนเงิน หักค่าธรรมเนียม และแก้ไขข้อพิพาทได้

**ยอดคุ้มครองงาน:** ยอดที่ลูกค้าชำระสำหรับงานและยังไม่พร้อมจ่ายให้ช่างจนกว่าจะเกิดเงื่อนไขปล่อยยอด หลีกเลี่ยงการเรียกว่า “Escrow” จนกว่าจะยืนยันรูปแบบทางกฎหมายและความสามารถของผู้ให้บริการรับชำระเงิน

เงื่อนไขปล่อยยอดใน MVP:

- ปล่อยยอดให้ช่างเมื่อลูกค้าตรวจรับงาน
- หากลูกค้าไม่ตอบสนอง ให้ปล่อยยอดอัตโนมัติเมื่อครบ 48 ชั่วโมงหลังช่างส่งมอบงานและแจ้งเตือนลูกค้าแล้ว
- หากลูกค้าเปิดข้อร้องเรียนภายในเวลาที่กำหนด ให้ระงับการปล่อยยอดของงานนั้นจนกว่าจะได้ข้อยุติ
- การคืนเงินและการจ่ายให้ช่างต้องมีประวัติที่ตรวจสอบย้อนหลังได้

รูปแบบรายได้ของแพลตฟอร์ม:

- ค่าคอมมิชชันจากค่าแรง 15% ต่อรายการใน MVP
- ค่าธรรมเนียมการจอง
- ค่าสมาชิกรายเดือนของช่าง
- ค่าโปรโมตโปรไฟล์หรือเลื่อนอันดับ
- ค่าบริการเร่งด่วน
- แพ็กเกจดูแลบ้านรายเดือนหรือรายปี
- ส่วนแบ่งจากการจำหน่ายวัสดุและอะไหล่
- แพ็กเกจสำหรับหอพัก คอนโด และบริษัทบริหารอาคาร

MVP หักค่าคอมมิชชัน 15% จากค่าแรงเมื่อปล่อยยอดให้ช่าง ไม่หักจากค่าวัสดุหรืออะไหล่ที่มีหลักฐานและลูกค้าอนุมัติ ลูกค้าเห็นราคาสุทธิที่ต้องจ่ายก่อนยืนยันโดยไม่มีค่าธรรมเนียมแฝง ช่างเห็นยอดรวม ค่าวัสดุ ค่าคอมมิชชัน และยอดรับสุทธิ อัตราต้องตั้งค่าได้สำหรับงานใหม่แต่ห้ามเปลี่ยนย้อนหลังกับงานที่ยืนยันแล้ว หากคืนเงิน ระบบต้องคำนวณย้อนกลับยอดช่างและค่าคอมมิชชันตามส่วนที่คืน

ยังไม่ใช้ค่าสมาชิกช่าง ค่าโปรโมตโพสต์ หรือแพ็กเกจรายเดือนใน MVP

## 11. ขอบเขต MVP

MVP ใช้รูปแบบ **ธุรกรรมครบวงจรผ่านแพลตฟอร์ม** ลูกค้าและช่างต้องยืนยันขอบเขตงานและราคาในระบบก่อนเริ่มงาน ค่าใช้จ่ายเพิ่มเติมต้องได้รับอนุมัติในระบบ และการชำระเงิน การตรวจรับ ตลอดจนสิทธิ์รับประกันต้องอ้างอิงกับงานในระบบ หลีกเลี่ยงการตกลงหรือชำระเงินนอกระบบเพราะทำให้แพลตฟอร์มไม่สามารถรับรองราคา คุณภาพ หรือการแก้ไขข้อพิพาทได้

เวอร์ชันแรกควรมี:

- แอปหรือเว็บ Mobile-first ที่รองรับบทบาทลูกค้าและช่าง พร้อมระบบผู้ดูแล
- ระบบสมัครสมาชิกและเข้าสู่ระบบ
- การสมัครช่างและส่งเอกสารยืนยันตัวตน
- การเพิ่มและเลือกสถานที่รับบริการ
- การแจ้งงานพร้อมรูปภาพ
- หมวดบริการเริ่มต้น 3 หมวด ได้แก่ เครื่องปรับอากาศ ประปา และไฟฟ้า
- การจับคู่ช่างตามหมวดและพื้นที่
- การรับงาน ปฏิเสธงาน และเสนอราคา
- การยืนยันราคาและนัดหมาย
- แชตระหว่างลูกค้ากับช่าง
- การเปลี่ยนสถานะและแจ้งเตือน
- รูปก่อนและหลังซ่อม
- การตรวจรับและชำระเงิน
- การพักเงินจนกว่าลูกค้าจะตรวจรับ หรือเป็นไปตามเงื่อนไขปล่อยเงินที่กำหนด
- การขอใช้สิทธิ์รับประกันและเปิดข้อร้องเรียนจากงานในระบบ
- คะแนนและรีวิว
- ประวัติงานของลูกค้าและช่าง
- Admin Dashboard สำหรับอนุมัติช่าง ตรวจสอบงาน และจัดการปัญหา

สิ่งที่ยังไม่จำเป็นใน MVP:

- AI วิเคราะห์อาการขั้นสูง
- ระบบประมูลราคาซับซ้อน
- โปรแกรมสมาชิกหลายระดับ
- Marketplace จำหน่ายอะไหล่เต็มรูปแบบ
- ระบบบริหารทีมช่างขนาดใหญ่
- บทบาทผู้ดูแลหอพัก คอนโด หรืออาคารและระบบองค์กรแบบเต็มรูปแบบ
- บริการฉุกเฉินหรือการรับประกันเวลาถึงหน้างาน
- การเปิดให้บริการพร้อมกันทั่วประเทศ

MVP เปิดตัวใน **เขตบริการนำร่อง** ที่มีขอบเขตจำกัดเพื่อควบคุมจำนวนช่าง คุณภาพบริการ และระยะเวลาการเดินทาง แต่ยังไม่กำหนดจังหวัด เขต หรืออำเภอในระยะออกแบบ ระบบต้องรองรับการตั้งค่าและเปลี่ยนเขตบริการได้โดยไม่ผูกกับพื้นที่ใดพื้นที่หนึ่ง และต้องเลือกพื้นที่จริงก่อนเริ่มรับสมัครช่างหรือเปิดบริการ

## 12. โครงสร้างหน้าจอหลัก

แนวทางภาพหลักใช้ Flat design แบบ mobile-first สีน้ำเงินเข้ม `#1E40AF` เป็นสีแบรนด์ สีน้ำเงิน `#2563EB` สำหรับ action สีส้ม `#EA580C` สำหรับ CTA สำคัญอย่างจำกัด พื้นหลัง `#F8FAFC` และแบบอักษร Noto Sans Thai รายละเอียด token และกฎ interaction อยู่ที่ `../design-system/homecare/MASTER.md`

## 14. เทคโนโลยีที่แนะนำ

Stack ของ MVP:

- Mobile App ลูกค้าและช่าง: React Native + Expo + TypeScript จาก codebase เดียว
- Admin Web: Next.js + TypeScript
- Backend, PostgreSQL, Auth, Storage และ Realtime: Supabase พร้อม Row Level Security
- Shared types และ validation ระหว่าง Mobile App กับ Admin Web
- แผนที่: เลือก Google Maps หรือ Mapbox ภายหลังและเชื่อมผ่าน adapter
- Notification: Expo Notifications และบริการ push ที่เกี่ยวข้อง
- Payment: Payment Gateway ที่รองรับช่องทางที่กำหนด โดยเชื่อมผ่าน adapter

ไม่ใช้ PWA เป็น client หลักของ MVP เนื่องจากแอปต้องพึ่งกล้อง push notification ตำแหน่งระหว่างเดินทาง และประสบการณ์ native บน iOS/Android การเลือกเทคโนโลยีนี้บันทึกใน `adr/0001-mvp-application-stack.md`

- MVP ใช้ภาษาไทยเป็นภาษาหลักสำหรับ Mobile App และ Admin Web โดยเว็บผู้ดูแลใช้คำเทคนิคอังกฤษได้เมื่อช่วยลดความกำกวม
- ข้อความในแอปใช้ translation keys และไม่ฝังข้อความกระจายใน component
- รองรับวันที่ เวลา ตัวเลข และเงินบาทตาม locale ไทย และจัดเก็บชื่อหมวดกับรายการบริการในรูปแบบที่แปลได้ในอนาคต
- ยังไม่เปิด UI ภาษาอังกฤษใน MVP แต่โครงสร้างต้องรองรับการเพิ่มภาษาโดยไม่รื้อหน้าจอ
- MVP ใช้ Light Mode เท่านั้น แต่ UI อ้างอิง semantic color tokens เพื่อเพิ่ม Dark Mode ภายหลังได้
- รองรับการตั้งค่าขนาดตัวอักษรและ Reduce Motion ของอุปกรณ์ และต้องทดสอบ contrast ในสภาพแสงกลางแจ้ง
- UI ต้องใช้งานง่ายสำหรับผู้ใช้ทั่วไปและช่างทุกช่วงวัย
- รองรับมือถือเป็นหลัก
- ระบบต้องมีสิทธิ์การเข้าถึงตามบทบาท
- ข้อมูลสำคัญต้องเข้ารหัสระหว่างส่งและจัดเก็บตามความเหมาะสม
- มีระบบสำรองข้อมูลและกู้คืน
- มี Logging, Monitoring และแจ้งเตือนข้อผิดพลาด
- รองรับการขยายหลายจังหวัดและหลายพื้นที่บริการ
- เก็บประวัติการเปลี่ยนแปลงข้อมูลสำคัญ
- รูปภาพควรถูกบีบอัดและควบคุมสิทธิ์เข้าถึง

## 16. กฎหมายและนโยบายที่ต้องเตรียม

- นโยบายความเป็นส่วนตัวตาม PDPA
- ข้อตกลงการใช้งานสำหรับลูกค้า
- ข้อตกลงและมาตรฐานบริการสำหรับช่าง
- นโยบายการยกเลิกและคืนเงิน
- เงื่อนไขการรับประกันงาน
- กระบวนการรับเรื่องร้องเรียนและข้อพิพาท
- หนังสือยินยอมเกี่ยวกับการเก็บและตรวจสอบข้อมูลยืนยันตัวตน
- เงื่อนไขการใช้ตำแหน่ง รูปสถานที่ และข้อมูลการชำระเงิน
- การประเมินหน้าที่ตามกฎหมายบริการแพลตฟอร์มดิจิทัลของ ETDA

ควรให้ผู้เชี่ยวชาญด้านกฎหมายในประเทศไทยตรวจสอบเอกสารและรูปแบบธุรกิจก่อนเปิดให้บริการจริง

## 17. ตัวชี้วัดสำคัญ

- จำนวนคำขอรับบริการต่อวันหรือเดือน
- อัตราการจับคู่ช่างสำเร็จ
- ระยะเวลาเฉลี่ยจนมีช่างรับงาน
- อัตราการยืนยันใบเสนอราคา
- อัตรางานเสร็จสมบูรณ์
- อัตราการยกเลิกแยกตามลูกค้าและช่าง
- ระยะเวลาเฉลี่ยตั้งแต่แจ้งงานถึงเสร็จงาน
- คะแนนความพึงพอใจเฉลี่ย
- อัตราการร้องเรียนและเคลมรับประกัน
- อัตราการกลับมาใช้บริการซ้ำ
- จำนวนช่าง Active และรายได้เฉลี่ยต่อช่าง
- GMV รายได้ค่าธรรมเนียม และกำไรต่อคำสั่งงาน

## 18. ความเสี่ยงหลัก

- จำนวนช่างในพื้นที่ไม่เพียงพอ
- คุณภาพงานและมาตรฐานของช่างไม่สม่ำเสมอ
- ช่างหรือลูกค้านัดหมายกันนอกระบบ
- ราคาเบื้องต้นไม่ตรงกับสภาพหน้างาน
- การยกเลิกหรือไม่มาตามนัด
- ความเสียหายต่อทรัพย์สินหรือความปลอดภัยภายในบ้าน
- ข้อพิพาทเรื่องขอบเขตงาน วัสดุ และค่าใช้จ่ายเพิ่มเติม
- ต้นทุนการตรวจสอบช่าง การบริการลูกค้า และการหาผู้ใช้สูง

แนวทางลดความเสี่ยงต้องถูกออกแบบไว้ในระบบตั้งแต่ต้น ได้แก่ การยืนยันตัวตน หลักฐานก่อน–หลัง การอนุมัติราคาเพิ่มเติม ระบบพักเงิน การรับประกัน และ Audit Log

## 19. Roadmap เบื้องต้น

### Phase 1: Validation

- สัมภาษณ์ลูกค้าและช่างในพื้นที่เป้าหมาย
- ทดสอบ 3 หมวดงาน ได้แก่ เครื่องปรับอากาศ ประปา และไฟฟ้า
- กำหนดมาตรฐานการรับช่างและราคาอ้างอิง
- ทดสอบงานจริงแบบ Manual หรือ Concierge Service

### Phase 2: MVP

- พัฒนาระบบลูกค้า ช่าง และผู้ดูแลระบบ
- เปิดใช้งานในพื้นที่เดียว
- เก็บข้อมูลการจับคู่ ราคา ระยะเวลา คุณภาพ และข้อร้องเรียน

### Phase 3: Growth

- เพิ่มพื้นที่และหมวดบริการ
- เพิ่มระบบรับประกัน การตลาด โปรโมชัน และสมาชิก
- ปรับปรุงระบบจับคู่ด้วยข้อมูลจากงานจริง
- เพิ่มแพ็กเกจสำหรับอาคาร หอพัก และคอนโด

### Phase 4: Scale

- แยกบริการ Backend เพิ่มเติมเมื่อ workflow, integration หรือปริมาณงานเกินขอบเขตที่ Supabase รองรับอย่างปลอดภัย
- เพิ่มระบบทีมช่างและพันธมิตรธุรกิจ
- เพิ่ม Marketplace วัสดุหรืออะไหล่
- เพิ่มระบบวิเคราะห์และคาดการณ์งานซ่อม

## 20. หลักการสำหรับการออกแบบและพัฒนาต่อ

- ให้ความสำคัญกับความน่าเชื่อถือและความปลอดภัยก่อนความซับซ้อนของฟีเจอร์
- ทุกงานต้องมีผู้รับผิดชอบ ขอบเขต ราคา สถานะ และหลักฐานที่ตรวจสอบย้อนหลังได้
- ห้ามเพิ่มค่าใช้จ่ายหลังเริ่มงานโดยไม่มีการยืนยันจากลูกค้า
- ออกแบบให้ผู้ใช้แจ้งงานได้เร็ว แต่ต้องเก็บข้อมูลเพียงพอให้ช่างประเมินงานได้
- ใช้แอปเดียวและกำหนดสิทธิ์ตามบทบาท หากผู้ใช้หนึ่งคนมีหลายบทบาทให้สลับบทบาทได้
- พัฒนา MVP จากกระบวนการที่เกิดขึ้นจริง ไม่เพิ่มฟีเจอร์ที่ยังไม่มีหลักฐานว่าผู้ใช้ต้องการ
- การขยายพื้นที่ควรเกิดเมื่อมีจำนวนช่างและทีมดูแลคุณภาพเพียงพอ
